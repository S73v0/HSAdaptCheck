# Local configuration

Copy `config/example.json` outside version control (for example `local/expected.json`). All clinical values are deliberately null or empty. `IndependentlyConfirmed` stays false until a physicist has independently established the expected inputs; setting it is a user assertion, not proof of independent review. Do not populate expectations by merely copying the same extracted adaptive plan being checked. Use independently confirmed prescription records, independently selected dataset identifiers and local commissioned machine/protocol specifications.

JSON property names are case-sensitive. Unknown properties are ignored by the serializer; they never supply missing expected values. Review the loaded version and full configuration in the exported report. Duplicate JSON member names and malformed JSON are unsupported inputs; use a validated editor and the supplied schema shape. There is no automatic migration of configuration versions.

- Set a unique `Version` and nonempty `ConfirmationSource` documenting the independent record/version without unnecessary patient details.
- `Reference` and `Adaptive` require exact plan UID, course ID, structure set UID, image UID and frame-of-reference UID. Course ID is a label, not a globally unique identity; plan/structure/image UIDs supply the independent dataset checks. Record these from trusted independent dataset selection. Do not use names as identity proxies.
- `OriginalCourse` and `AdaptiveSegment` are separate. Their fractions are planned counts, not delivered or remaining fractions. Dose per fraction is in Gy, with a nonnegative explicit absolute `DoseToleranceGy`. Target total-dose levels are recorded individually; v0.1 cannot extract/verify their linkage from ESAPI and always reports them NOT VERIFIED. Multiple dose-level prescriptions must not be interpreted as verified by a matching global dose per fraction.
- `RequiredStructures` entries have `Key` and `AllowedIds` arrays. Complete all locally required source targets, nodal targets, Limbus OARs and planning structures as applicable. No names are prescribed by this repository. Example shape only: `{"Key":"LOCAL_ROLE","AllowedIds":["LOCAL_ID"]}`. Matching is case-insensitive; zero matches or empty structures fail; multiple matches, overlapping aliases and duplicate role keys fail. Volume is descriptive only. Non-empty is not an anatomical correctness check.
- `Algorithm` is the exact commissioned algorithm string. Grid X/Y/Z and `GridToleranceMm` are in mm. These compare the stored dose lattice spacing, which must be commissioned against the intended calculation grid and API semantics locally. A missing or unsupported property is NOT VERIFIED; it does not pass by fallback.
- `BeamCount` excludes setup fields. `Beams` contains one explicit expectation per treatment beam: `Id`, exact `Machine`, exact `Energy`, `Mu`, `Xmm`, `Ymm`, `Zmm`. `MuTolerance` is absolute MU; `PositionToleranceMm` is absolute per-coordinate tolerance, not radial distance. Missing tolerances cannot pass. Dose, grid and expected MU must be positive. Coordinates use ESAPI image DICOM coordinates in mm, not user/display coordinates; establish expectations in the correct CBCT frame. No beam ID or machine default is supplied.
- `ExpectedChangeRationale` documents intended adaptation changes. Change rows remain REVIEW even when rationale exists. Exact adaptive expectations still detect discrepancies; rationale cannot override a FAIL. Beam-ID pairing in descriptive deltas does not prove field correspondence or comparable coordinate systems.

PASS means that specific implemented comparison succeeded using available evidence; it never means treatment release. REVIEW requires interpretation. FAIL identifies a mismatch/required missing item. NOT VERIFIED identifies incomplete, unsupported, unconfirmed or failed extraction/configuration evidence. There is no overall PASS label. Dose currency is always NOT VERIFIED in this version.
